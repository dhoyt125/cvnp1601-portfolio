The devuser account was created with useradd -m -G developers -s /bin/bash devuser, assigning a system-generated UID, /bin/bash as the login shell, and a home directory at /home/devuser (mode 700, owned by devuser). Group membership was verified with id devuser, confirming developers appears in the account's supplementary group list. A scoped sudo rule was written to /etc/sudoers.d/devuser-service-restart via visudo, granting exactly one command: devuser ALL=(root) NOPASSWD: /usr/bin/systemctl restart nginx, using a full binary path and fixed arguments with no wildcards. Testing confirmed the allowed command, sudo -u devuser sudo /usr/bin/systemctl restart nginx, succeeded with exit code 0, while systemctl restart sshd and systemctl stop nginx were both denied — proving the rule is scoped to one exact action, not the service or command family. sudo -u devuser sudo -l returned a single matching line with no ALL, confirming no over-grant.
